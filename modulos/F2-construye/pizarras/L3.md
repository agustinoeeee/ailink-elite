Pie: *Al fontanero no le dices qué llave inglesa usar. Le dices que la ducha pierde agua.*

## D4 — El brief: seis secciones, siempre las mismas
Lista numerada, columna vertebral de la lección. Son las mismas 6 secciones que el alumno se descarga: reutiliza la composición del A4 `plantilla-brief-solucion` en horizontal.

1. Contexto  
2. Qué debe hacer  
3. Qué NO entra  
4. Datos de ejemplo  
5. Aspecto  
6. Cómo sabré que funciona

Letra pequeña: *La 2 es el corazón. "Comportamiento observable" significa algo que se puede VER pasar en pantalla y comprobar con un sí o un no.*

Pie: *La calidad de lo que Claude Code construye es un espejo exacto de la calidad de tu brief.*

PROBAR ANTES DE PEDIR EL SIGUIENTE

Letra pequeña: *Si pides cinco cambios a la vez y algo se rompe, no sabes cuál de los cinco fue. Si pides uno, lo sabes siempre.*

## D6 — CLAUDE.md: las reglas fijas de tu proyecto
Tres líneas, lo que se escribe dentro:

- Qué es el proyecto y para quién  
- Reglas fijas  
- Qué no debe tocar

Letra pequeña: *Un texto que Claude Code lee SIEMPRE antes de ponerse a trabajar. Se pide en lenguaje natural: "crea el CLAUDE.md de este proyecto con estas reglas: …".*

Pie: *Es el manual de bienvenida del becario. Se lo das el primer día y no se lo repites cada mañana.*

## D7 — Los 5 errores del no-técnico (héroe: se tachan uno a uno)
1. Pedirlo todo de golpe  
2. No probar entre cambios  
3. Aceptar sin revisar  
4. Pelearse con el error en vez de pegárselo a Claude  
5. Cambiar de idea a mitad sin actualizar el brief

Pie: *Los conoces antes de cometerlos: esa es tu ventaja sobre el 90% de la gente que abre esta herramienta.*
